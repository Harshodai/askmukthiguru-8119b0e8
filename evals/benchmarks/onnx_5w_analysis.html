Why — Problem / Solution Matrix

⚠ PyTorch cold-start latency

PyTorch JIT compilation + caching allocator initialization cause 42-245ms variance on cold cache. ONNX Runtime has no JIT — graph optimizations are pre-applied at session creation. Result: 26ms P95, 3.4x lower standard deviation.

✅ Deterministic inference

ONNX Runtime is deterministic: same input always produces same latency (no JIT, no dynamic graph). fp32 PyTorch varies by 40x in variance (1,259 vs 32 ms²). Production monitoring becomes reliable.

⚠ Memory pressure on Railway

BGE-M3 fp32 occupies ~2.8 GB resident memory. On a single-replica Railway deploy (typically 1-2 GB RAM), this leaves insufficient headroom for other services. INT8 reduces to ~750 MB.

✅ 4x smaller container images

ONNX model: 8 files, 560 MB. fp32 FlagEmbedding: 30+ shard files, 2.2 GB. Fewer files means faster container startup, less HF cache corruption risk, simpler cache management.

⚠ Thread pool contention

PyTorch's ATen thread pool (even with OMP_NUM_THREADS=1) adds ~50-100ms overhead on first parallel operation. ONNX Runtime manages its own thread pool with clean inter_op/intra_op separation.

✅ No GPU requirement

Railway CPU-only deployment. ONNX Runtime's CPUExecutionProvider is the most mature CPU inference engine. GPTQ/AWQ require GPU. GGUF ties to llama.cpp ecosystem. ONNX is portable.

⚠ Embedding quality preservation

INT8 quantization can degrade retrieval accuracy. Validated at cos 0.9885 mean, 0.9154 top-10 overlap — within acceptable thresholds. The multi-vector output (dense + sparse) preserves hybrid search quality.

⚠ ColBERT offline (cp1 limitation)

The model outputs colbert_vecs but the pipeline doesn't use them for reranking yet. tracked as formal release blocker. Dense-sparse hybrid (RRF fusion) is the active path.

DimensionRationale
Cost Reduced memory footprint allows Railway to run on smaller instances (lower monthly cost). Faster inference means fewer CPU-seconds per request, reducing Railway resource usage.
Latency 7x faster cold-start, 2x faster warm. Directly improves user-perceived response time — the embedding step is on the critical path for every chat query.
Reliability Eliminates PyTorch/FlagEmbedding version incompatibilities (2026-07-16 incident: HF cache corruption caused silent dimension mismatch). Dimension validation is built into the ONNX loader.
Determinism ONNX Runtime produces identical outputs for identical inputs across runs. No JIT, no dynamic graph, no random seed effects. Makes A/B testing and regression detection reliable.
Portability Same ONNX model file works on macOS, Linux, Windows, ARM, x86. No CUDA dependency. Railway deploys on Linux AMD64 — the model runs unchanged.
Risk Low risk: toggle-controlled (EMBEDDING_BACKEND=onnx_int8), validated against 380-query corpus, verified dimension match to Qdrant collection. Rollback is a single env var change.
