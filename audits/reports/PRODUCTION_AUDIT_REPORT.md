# Mukthi Guru — Production Readiness Certification Report

**Audit type:** Read-only, live local dev stack (Qdrant + Neo4j + LightRAG + Supabase), full static code inspection, adversarial red-team-the-red-team verification pass on every finding.
**Date:** 2026-09-04
**Scope:** 18 independent dimension audits + 1 unknown-unknown sweep, all findings independently re-verified against live data and live source before inclusion.

## 1. EXECUTIVE VERDICT: **NOT PROD READY**

Two confirmed P0s each independently violate this project's foundational invariant — that a seeker is shown either grounded doctrine or an honest abstention, never fabricated confidence. **F1** shows `generate_answer`'s tier2/fast faithfulness check fails open on any LettuceDetect exception, fabricating a `faithfulness_score=1.0`/`confidence_score=10.0`/`verification.passed=True` result that sails through the downstream gate specifically hardened against blanket-accepts — on the code's own documented ~73%-of-traffic fast path. **OKF-1** shows the doctrine review pipeline is structurally disconnected end-to-end (636 staged, LLM-synthesized entries sit in a filesystem directory the admin review API can never see, because that API only reads a Supabase table nothing ever writes to) — making `--auto-approve` the *only* live path for LLM-generated content to reach the doctrine injected verbatim into chat answers, which is exactly the unreviewed path CLAUDE.md's own invariant warns against. On top of these, 13 confirmed P1s span a live 68.9%-contaminated retrieval collection, a Neo4j graph whose typed ontology has zero live representation, a broken multi-tier checkpoint fallback, a security-mitigation regression reintroduced in the working tree, and three tests that would stay green through the exact regressions they claim to guard. None of this was chaos- or load-tested; all of it is reasoned from live data and live code, not speculation. This is not a borderline call — it is not conditionally ready either, because both P0s are live-reachable on the majority code path today, not edge cases requiring rare preconditions.

## 6. RELEASE BLOCKERS

### F1-A — Fail-open faithfulness fabrication (P0)
- **Problem**: any exception in the tier2/fast LettuceDetect call causes `generate_answer` to fabricate a perfect faithfulness score, which the downstream gate cannot distinguish from a real one.
- **Why it blocks**: this is the core anti-hallucination promise of the product, broken on the majority traffic path, silently, with no log signal distinguishing it from a genuine pass.
- **Minimum remediation**: in the exception handler (`generation.py:2004-2013`), set `faithfulness_score=None` (not a float) and route to the existing abstain/needs-correction path instead of fabricating `passed=True`. Ensure `format_final_answer`'s `measured` check treats `None` as unmeasured, which it already does — the bug is only in what the handler assigns.
- **How to verify**: unit test that forces `lettuce_detect.score_faithfulness` to raise inside `generate_answer`'s tier2 branch, and asserts the final `format_final_answer` output has `grounding_state != "verified"` / an honest low-confidence or abstained result.

### OKF-1 — Doctrine review pipeline disconnected (P0)
- **Problem**: extraction writes to filesystem `staging/`; the admin review API reads/writes a Supabase table with no producer. 636 entries are stuck with no reachable review path.
- **Why it blocks**: forces `--auto-approve` as the only way LLM-synthesized doctrine ever reaches `compiled.json` and is injected verbatim into live answers — the exact unreviewed-content risk the project's own doctrine invariant exists to prevent.
- **Minimum remediation**: either (a) make extraction insert a Supabase `okf_review_queue` row per staged file with a stable id the approve endpoint can act on, or (b) repoint the admin review API to list/approve directly against the filesystem `staging/` directory. Add an integration test that runs a real `extract_okf()` call and asserts the resulting entry is visible via `GET /api/admin/okf/review`.
- **How to verify**: stage one real entry via the extractor, confirm it appears in the admin review list, approve it via the API, confirm it moves to `memory/okf/` and survives `compile_okf()`.
