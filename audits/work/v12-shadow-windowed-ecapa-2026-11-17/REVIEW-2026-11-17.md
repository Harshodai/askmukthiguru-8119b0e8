## Findings

### F1 — P0 (governance): 12 spans claim `verified` with zero evidence, in breach of the write rule
The 12 legacy-centroid rows whose served window is out of bounds returned
`indeterminate_no_windows` (`out_of_bounds`) from the windowed scorer and were correctly skipped by
the writer. They were then stamped `speaker_verification_status=verified` by a separate "DQ fix"
(`ingestion_wiring_report.json`), with no voice score, no calibration id, no model revision and no
window check.

Live check: all 12 return `speaker_write_violations(payload) == ["legacy_method_refused:ecapa_voxceleb_centroid_v1"]`.
The repo's own rule refuses exactly these payloads, and invariant 23 requires `speaker_verified`
to come from stored evidence. The status stamp makes an indeterminate record look verified and is
not reproducible from any committed script.

Recommended: demote the 12 to `speaker_verified=false` / `pending_voice_check` (their served window
does not exist, so nothing can be certified), or leave the inconsistency OPEN and recorded. Do not
keep a synthetic `verified`. The pre-fix values are only in the 04:15 snapshot — the DQ fix has no
row-level backup.

### F2 — P2: the stored `voice_score` is the span mean, not the gate statistic
The gate is "every window passes", but the 555 windowed rows store `span_cosine_mean` as
`voice_score`. On the verified sample the mean sits a mean 0.1055 above the worst window
(0.1055 gap, n=119). An auditor comparing `voice_score >= cosine_floor` is therefore checking a
number that is not the gate. Store the minimum window cosine (or add a `voice_window_min` field)
so the payload names the weakest window that was accepted.

### F3 — P2: `voice_verified_at` is written on refused spans
All 1,311 `ecapa_failed` rows carry `voice_verified_at` = the apply timestamp. A span that was
never verified should not claim a verification time. This pre-dates the windowed work but this run
wrote 1,311 of them.

### F4 — P1 (calibration validity): the negative filter is the same number as the calibrated floor
Negatives were excluded when their best cosine to *any* teacher reference was ≥ 0.50
(`NEGATIVE_COSINE_CONTAMINATION_THRESHOLD`, the "probably mislabelled teacher" filter).
Observed: max negative cosine 0.4991, 165 negatives in
0.45–0.50, and the calibrated floor is 0.492987. The 1% FAR therefore describes only the surviving
distribution; the strongest host-speech windows — the failure mode this method exists to catch —
were removed before calibration and their count was not recorded.

Recommended: record the excluded count and cutoff in the calibration artifact, state the FAR as
conditional on that filter, and validate on a held-out diarized set where no contamination filter
is applied.

### F5 — P2 (reporting): the gate's operating unit is the span, but the calibration reports windows
94.99% is the window pass rate. The span rule (all windows pass) passes 59.5% of the prior verified
set, and 46 of the 81 sample refusals had exactly one failing window — so a tolerance of 1 would
have flipped more than half of them. That is an owner decision, not a default; it was correctly not
taken, but the span-level number is what the owner needs to see and it is absent from the artifact.

### F6 — P1 (mixed evidence standard): the shadow now carries two standards
841 rows still claim verification under `span_slice_v2`, a method a 200-row sample shows would
fail the new rule 40.5% of the time (95% CI for the 841: ~443–558 would survive). The prompt asked
for the whole shadow under one method. It is not. Consequence for the headline:

* 1,408 / 2,719 = 51.78% as stored;
* 1,396 / 2,719 = 51.35% if the 12 F1 rows are excluded;
* ~1,055 / 2,719 ≈ 38.8% (95% CI 36.7–40.9%) if the 841 were re-gated with the windowed rule.

Any single "verified share" figure is ambiguous until the 841 disposition is decided. Nothing was
silently downgraded, which is correct.

### F7 — P2 (ingestion wiring): the new default verifier is unreachable inside the container
`WindowedEcapaVerifier._load_scorer()` inserts `parents[2]` (= `/app`) and imports
`scripts.ops.windowed_ecapa_v1_scorer`. In the container `/app/scripts` is the repo-root bind mount
(backend/scripts is shadowed, exposed only as `/app/backend_scripts`), and the scorer plus
`regenerate_v10_span_ecapa_verdicts` exist only in `backend/scripts/ops`. Demonstrated failure:

```
$ python3 -S -c "sys.path=[<tree with only repo-root scripts>]; import scripts.ops.windowed_ecapa_v1_scorer"
ModuleNotFoundError: No module named 'scripts.ops.windowed_ecapa_v1_scorer'
```

The builder catches the failure and logs one warning, then uses `span_slice_v2` for the whole run.
No bad evidence is written, but "default is windowed_v1" is true only on a host venv whose editable
install puts `backend/` on `sys.path` — and the default references live at
`~/mukthiguru_attribution_data/…`, which the container does not mount. Either add the
`backend_scripts.ops.*` anchor to the import (both files, or a file-path load), or mirror both files
into `scripts/ops/` and pin them, and make the fallback loud plus recorded per run.

### F8 — P2 (tests): the new writer has no test
`decide_windowed()` wrote all 555 verified claims and is not covered by
`tests/test_apply_shadow_voice_verdicts.py` (that file still tests only `decide()`). Also missing:
a test that a verifier payload passes `assert_speaker_write_allowed`, and a test of the builder's
`--verifier` selection/fallback. The 105 passing tests are real but do not touch this.

### F9 — P3: windowed verdicts are not re-checkable
`decide_windowed()` returns `not_pending` for any row already `windowed_v1`, so a re-run with a new
calibration keeps the old verdicts. A re-check needs a method-version bump or an explicit override.

### F10 — P3: positives are not the set the prompt named
The prompt asked for a random sample of ≥300 **v10** span-slice-verified spans; the run sampled the
shadow's own 841 `span_slice_v2` spans. Same ECAPA model, same references, so positives are
model-selected rather than independent; the 94.99% is therefore optimistic, which does not affect
the FAR.

## What is solid

* Fail-closed is real: missing calibration, missing WAV, no audio dir, unknown guru, embedder
  exception and zero non-silent windows all return `pending_voice_check`, never `verified`.
  The embedding-failure window path scores as a mismatch, never a pass.
* The silence rule is stated, single-valued and tested; only 11 windows were skipped across the
  200-span sample, so it is not hiding refusals.
* Strict `max_failing_windows=0` was kept rather than tuned to make numbers look better.
* Calibration artifact is pinned, hashed, and byte-identical to the copy the code loads.
* Snapshot + per-row before-export exist for everything the writer touched; the writer refuses any
  collection but `first_person_v12_shadow`, refuses `--apply` without a snapshot, and routes every
  write through `assert_speaker_write_allowed`.
* `ecapa_voxceleb_windowed_v1` is registered with the full span-slice provenance checks; a
  verified payload missing score, margin, model revision, calibration id or floor is refused.
* No v10/v8/OKF/Redis/serving-config write in this work.
