## 1. The Goal We Are Working Toward

The core mission of AskMukthiGuru is to deliver an **Ask-Sadhguru-quality, zero-hallucination first-person spiritual companion** grounded exclusively in the authentic recorded wisdom of Sri Preethaji and Sri Krishnaji.

### Non-Negotiable Core Invariants:
1. **The Living Teachers Speak Directly**:
   - When a seeker asks a spiritual question (suffering, love, meditation, inner peace, relationships, oneness), the system serves the **teachers' actual recorded words** from discourses, interviews, and guided sessions.
   - **Zero LLM text generation** in the guru's persona. The LLM acts exclusively as an offline indexer or a strict binary ranking/answerability verifier, never authoring spiritual teachings.
2. **Preserving the Sacred Guru State**:
   - Spoken discourses convey an awakened state of connection. Text slicing must never sever trailing coordinating conjunctions (`"or"`, `"and"`, `"so"`, `"but"`) or emit truncated clause fragments.
   - Clips maintain philosophical context (rolling target 18–25 seconds) capturing both the diagnostic premise and the spiritual practice.
3. **Verbatim Provenance & Deep Links**:
   - Every quoted sentence must be an exact substring of a speech-turn clip in Qdrant with `transcript_hash == sha256(cleaned_text)`.
   - Every quote links directly to the verified YouTube second (`&t=...s`).
4. **Honest Abstention Over Fabrication**:
   - If the corpus lacks a direct, relevant answer, the pipeline must **honestly abstain** (`grounding_state = "abstained"`), falling back to general RAG or compassionate boundary responses rather than hallucinating doctrine.
5. **Corpus Scale & Quality Target**:
   - Expand from the 144 pilot clips in `first_person_v7` to ~2,500 high-fidelity clips spanning **634 rights-cleared videos** (515 core inventory + 119 latest 2026 discourses).
6. **Local Production Readiness Only**:
   - All verification is local. Remote Railway production remains untouched until local readiness is proven.

## 4. Everything Tried, Failed, and Root-Caused

| Incident / Attempt | Failure Mode | Root Cause Analysis | Corrective Architectural Fix |
| :--- | :--- | :--- | :--- |
| **1. Docker Container Embedding Crash** | Container terminated with exit 137 (`OOMKilled`) twice during reconciliation. | Loading FastEmbed, PyTorch, ONNX, and BGE-M3 inside the backend container pushed memory past the enforced 6 GiB cgroup limit. | **Strict Host-Side Invariant (`L-HOST-EMBED-1`)**: All batch embedding and reconciliation must run host-side via `backend/.venv/bin/python3`, utilizing 32+ GB unified RAM and Metal acceleration. |
| **2. YouTube 429 Bot Challenges** | Default `yt-dlp` scraping was blocked by YouTube with HTTP 429 after ~30–50 consecutive downloads. | YouTube web client endpoints (`WEB`) enforce aggressive TLS fingerprinting and request rate heuristics against scrapers. | **Mobile Client Extractor (`L-YTDLP-MOBILE-1`)**: Added `--extractor-args "youtube:player_client=android,ios,mweb,web"`. Mobile endpoints bypass web bot challenges without authenticated cookies. |
| **3. Circuit Breaker False Positives** | Downloader circuit breaker halted downloads even when `yt-dlp` succeeded. | `yt-dlp` emits harmless warning logs during client fallback; the circuit breaker inspected text output regardless of return code. | **Status Code Gating**: Updated circuit breaker to only trigger when `proc.returncode != 0 and is_blocked`. |
| **4. Process Suspension on Machine Sleep** | Workers stopped during overnight run with `Failed to resolve 'www.youtube.com'`. | When macOS slept, network DNS dropped. The single-pass runner iterated through candidates, recorded failures, and exited upon reaching the end. | **Continuous Resilience Loop (`--continuous`)**: Added `--continuous` flag. Workers now back off, wait for cooldown expiry, and automatically retry until 100% of candidates succeed. |
| **5. Age Gate Misclassified as Bot Rate Limit** | Video `rQLQKMUUTMM` repeatedly triggered 300s bot cooldowns. | YouTube output `"Sign in to confirm your age"` was caught by a loose `"Sign in to confirm"` substring match intended for bot captchas. | **Dedicated Age Gate Classification**: Added explicit `is_age_restricted` branch; marked `status: age_restricted` without penalizing the worker cluster. |
| **6. Out-of-Corpus Trivia Leaking into Persona** | Audit D showed "What is the capital of France?" returning teacher discourse. | Dense vector nearest-neighbor search always returns non-zero cosine distance (~0.46) on small corpora due to conversational tokens. | **Two-Tier Abstention Gate & Bridge Kill-Switch (`L-ABSTAIN-1`)**: Engaged kill-switch (`FIRST_PERSON_CHAT_BRIDGE_ENABLED=false`); designed cross-encoder + binary LLM answerability verifier. |
| **7. OKF Doctrine Quote Fabrication** | 27 of 38 audited OKF quotes were LLM paraphrases never spoken by teachers. | LLM extraction pipeline summarized concepts and wrapped them in quotation marks attributed to Sri Preethaji. | **Phase 3 OKF Verbatim Repair**: Replaced unverified quotes with exact transcript substrings or purged fabricated quote markers. |

## 5. What Was Learned & Experimental Results

1. **Audio Acquisition Throughput**:
   - 2 concurrent workers using consistent hash partitioning (`int(sha256(vid)[:8], 16) % 2`) achieved **~6.8 videos / minute** combined throughput.
   - 680 videos (68.56 hours of audio) were processed with **zero inter-process lock contention** and **zero duplicate downloads**.
2. **Apple Silicon Hardware Acceleration**:
   - `whisper-medium` + `parakeet-tdt-1.1b` running on Apple Silicon Metal/MPS + MLX achieves **15x–25x realtime transcription speed** locally.
   - 68.5 hours of audio will transcribe in approximately **2.7 to 4.5 hours of local wall-clock compute**, completely eliminating the previously estimated 2–4 day bottleneck.
3. **Decoupled Architecture Payoff**:
   - Separating raw audio acquisition (`AudioArchive`) from feature extraction and ASR ensures that transient network failures never require re-running expensive ML pipelines, and model upgrades never require re-downloading audio.
