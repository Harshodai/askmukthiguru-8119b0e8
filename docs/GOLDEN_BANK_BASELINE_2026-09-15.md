# Golden-bank baseline — 2026-09-15

Numbers, not targets. Re-measure before citing; they decay.

## Instrument

`backend/evaluation/golden_qa_bank.json` — 34 **hand-written** questions with
reference answers, `must_mention` keyword constraints and `reject_if`
confabulation guards, across 9 doctrine/safety categories.

Use this set, not `golden_dataset.json` (589 items), for accuracy claims. The
larger set's questions were generated by an LLM from sampled chunks, so it
measures self-consistency, not correctness (TrustNLP F18). The 34-item bank is
the only non-circular instrument in the repo.

Every request sent `cache_bypass: true`. **`incognito` is NOT a cache bypass** —
it is a privacy flag (no memory write, no history persist). An eval that sets
only `incognito` measures Redis. See `docs/EVAL_PRECONDITIONS.md`.

## Baseline (host uvicorn, all four stores healthy, serial)

Taken with the faithfulness fixes in and **before** the CRAG rewrite fix.

| Metric | Value |
| :--- | :--- |
| Refusal rate | **38%** (13/34) |
| Doctrinal contradictions (`reject_if`) | **0/34** |
| `must_mention` coverage, answered only | **0.54** |
| `must_mention` coverage, all items | **0.38** |
| Latency p50 / p95 / max | **39s / 117s / 135s** |

"Refusal" = the seeker got the verification-gate excerpt boilerplate or a bare
"I don't have that specific teaching", not a teaching.

The zero contradiction count is the one genuinely good number here: the system
does not fabricate wrong doctrine. It declines instead — too often.

## All four retrieval lanes are live

Per-lane counters now ride in `evaluation_trace` (`okf_injected_count`,
`kg_context_chars`, `lightrag_context_chars`). `0` means the lane ran and found
nothing; `None` means it was never reached — the distinction needed to debug a
bad answer.

| Lane | Contributed on |
| :--- | :--- |
| Qdrant | 34/34 (every answer) |
| OKF | 30/34 |
| Neo4j subgraph | 26/34 |
| LightRAG | 19/34 |

Before these counters the only way to answer "is LightRAG actually used?" was to
grep server logs. A first attempt at this table reported Neo4j as dead on every
query — that was a missing key in the eval harness, not the system. Confirm a
lane is dead from the backend log *and* the trace before believing it.

## Refusal correlates with latency, and the cause was CRAG

| | n | median latency | over 60s |
| :--- | ---: | ---: | ---: |
| Refused | 13 | **82s** | 8/13 |
| Answered | 21 | **25s** | 2/21 |

16 CRAG rewrites fired during the run. **14 of 16 returned the model's chat
preamble as the search query**:

```
CRAG rewrite #1: Connect the fourth sacred secret... -> Here is the rewritten query:\n\nConnect the fourth s...
CRAG rewrite #2: Here is the rewritten query:\n\nConnect... -> Here is the rewritten query:\n\nConnect...
```

`_REWRITE_LABEL` anchored on `rewritten query` at position 0, so a leading
"Here is the " meant nothing was stripped. `rewrite_query` feeds
`state["rewritten_query"]` back in as the next pass's input, so pass 2 stacked a
second preamble on the first. Each poisoned pass costs a retrieval plus an LLM
call (one measured at 26.1s) and then retrieves against the preamble text.

`QUERY_REWRITE_PROMPT` already ends with "Return ONLY the rewritten query,
nothing else." The model ignored it. Never trust an LLM's output format — parse
and validate it. The rules now live in a pydantic `RewrittenQuery` model
(`rag/nodes/short_circuit.py`); construction failing is the expected outcome for
a bad rewrite, and the caller falls back to the seeker's original question,
which is always valid.

## Reproduce

```bash
cd backend && REDIS_URL="redis://:...@localhost:6379/0" QDRANT_URL=http://localhost:6333 \
  NEO4J_URI=bolt://localhost:7687 .venv/bin/uvicorn app.main:app --port 8000
# then, from the repo root:
backend/.venv/bin/python scripts/eval/golden_bank_eval.py http://localhost:8000
```

Report lands at `backend/benchmarks/reports/golden_bank_eval.json`.
