## How to record a decision

1. Fill only the blank columns (`decision`, `reviewer`, `date`, `notes` — or the packet's named
   equivalents). Never edit the source columns: a packet whose input columns changed is no longer
   traceable to the hash in `PROVENANCE.json`.
2. For the helpline packet, `live_call_made_yyyy_mm_dd` is the only column that can change
   `last_verified_by_call` in `config/helplines.yaml`; a date typed without a call is a false claim.
3. For the rights packet, `approve` means the registered basis is correct and the attribution
   requirements are met. `exclude` means stop serving. `hold` means keep out of serving until
   resolved. Absence is not `approve`.
4. Return the filled file; the owner records the outcome in
   `docs/plans/PROD_READINESS_TASK_LIST_2026-10-11.md` §24 and `docs/analysis/OUTSTANDING_ISSUES.md` §4.

## Regenerating

```bash
python3 scripts/ops/build_human_review_packets.py \
    --out-dir docs/reviews/2026-11-14-human-gates \
    --rows ~/mukthiguru_attribution_data/graded_runs/20261114-graded-7/rows.jsonl \
    --crisis-copy-json docs/reviews/2026-11-14-human-gates/crisis_copy_probe.json
```

Omit `--rows` to skip the answer sample. The sample is drawn only from rows that served a clip: an
abstained row has nothing to judge.

## What a packet cannot do

- It cannot certify itself. A filled packet is a record of a human decision, not a measurement.
- It cannot fix a bar. `20261114-graded-7` is an **invalid** run (`run valid: False`), so even a
  perfect human sample does not turn it into a PASS.
- It cannot replace the native-speaker crisis review with an LLM judgement. `OUTSTANDING_ISSUES.md`
  §4 says the same thing.
