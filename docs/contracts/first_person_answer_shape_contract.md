## 1. Overview & Purpose

This contract establishes the normative shape, markdown formatting rules, and structured JSON schemas for first-person verbatim answers in AskMukthiGuru. It fulfills Tasks **F4** and **E6 framing** from `docs/plans/MASTER_PLAN_FP_ROUTING_PROFILE_2026-10-17.md` and provides Thread T5 with an immutable specification to render against.

Every teaching sentence served under this contract is an **unaltered, byte-identical transcript excerpt** from recorded discourses of Sri Krishnaji and Sri Preethaji, verified by cryptographic hash against `transcript_hash`.

---

## 2. Serving Surfaces

First-person answers are delivered across two distinct surfaces:

| Surface | Endpoint | Return Type | Consumer Component |
|---|---|---|---|
| **Direct First-Person Route** | `POST /api/first-person/query` | `FirstPersonQueryResponse` | `TeacherWords.tsx`, `firstPersonService.ts` |
| **Main Chat Route** | `POST /api/chat`, `POST /api/chat/stream` | `PipelineResult` (via SSE / JSON) | `ChatPage.tsx`, `ChatMessage.tsx` |

Both surfaces deliver identical markdown formatting in their primary text field (`answer_text` on Direct Route, `final_answer` on Chat Route) and identical structured citation / audio clip arrays.

## 3. Markdown Continuous Layout Contract (Task F4 / Master Plan §4)

The old card-based layout with inline markdown URLs (formerly generated by `_format_clip_block`: `**Label** · [Title](URL)`) is **RETIRED**. The continuous layout presents one coherent, non-fragmented reading experience modeled on clean editorial typography.

### 3.1 Structural Grammar

A complete answer is composed of up to six sequential sections:

```markdown
[Optional 1-line Framing — visibly ours, default OFF]

### On <Facet or Topic 1>
> <Verbatim transcript quote, byte-identical to transcript_hash>
— <Speaker Label> · <Talk Title> · ▶ <MM:SS>

### On <Facet or Topic 2>
> <Verbatim transcript quote, byte-identical to transcript_hash>
— shared in <Channel Name> (unverified speaker) · <Talk Title> · ▶ <MM:SS>

### On <Facet or Topic 3>
I don't have a recording that answers this part yet.

Related, not a direct answer
---
Sources: [1] <Talk Title> @ <MM:SS> · [2] <Talk Title> @ <MM:SS>
```

### 3.2 Layout Invariants & Parsing Rules

1. **Optional Framing Line (`FIRST_PERSON_FRAMING_ENABLED`, default OFF)**:
   - When enabled, an LLM synthesizes at most 1 line acknowledging the question structure (e.g. `[Your question has three parts: suffering, love, prosperity.]`).
   - Must be enclosed in square brackets `[...]` or formatted as a top italicized lead.
   - **Invariant 1 / Rule 2**: Framing lines NEVER make doctrinal claims, paraphrase spiritual teachings, or assert philosophical conclusions.
   - Frontend styling: Muted gray / secondary text, visibly separated from guru quotes.

2. **Facet Headings (`### On <Topic>`)**:
   - For multi-part or compound questions, each facet begins with a level-3 markdown heading `### On <Topic>`.
   - For single-topic questions, the heading may be omitted or represent the primary concept (e.g. `### On suffering and meditation`).

3. **Verbatim Quote Block (`> Quote`)**:
   - Every quote line is rendered as a standard markdown blockquote prefixed with `> `.
   - **Invariant 2 / Rule 1 (Byte-for-Byte Exactness)**: The text inside the blockquote MUST match the transcript slice corresponding to `transcript_hash` byte-for-byte. No punctuation changes, no capitalization edits, no trimming of conversational starters (e.g., "Yes," or "So,"), and no bracketed clarifications `[...]`.
   - **No Mid-Sentence URLs**: Quote text and attribution headers MUST NOT contain markdown links `[link](url)`. Raw URLs mid-sentence break immersion and are strictly forbidden.

4. **Attribution Line (`— Speaker · Talk Title · ▶ MM:SS`)**:
   - Directly follows the quote block.
   - Prefixed with an em-dash `— `.
   - **Speaker Verification Invariant (Invariant 17 / E4)**:
     - When `speaker_verified == True`: Display official name (e.g., `— Sri Krishnaji · The Beautiful State · ▶ 01:12`).
     - When `speaker_verified == False` or channel is unverified: MUST display channel context, e.g.:
       `— shared in Ekam Channel (unverified speaker) · The Beautiful State · ▶ 01:12`
     - Never fabricate a bare teacher name without verified voiceprint or authorized channel origin.
   - **Timestamp Pill (`▶ MM:SS`)**:
     - Includes play symbol `▶ ` followed by formatted minutes:seconds or hours:minutes:seconds.
     - Serves as the visual anchor for playback.

5. **Per-Part Honest Abstention**:
   - If a specific facet cannot be answered with verified clips meeting relevance $\ge 3$ and passing the answerability gate:
     `I don't have a recording that answers this part yet.`
   - **Rule 2 / Invariant 21**: Under no circumstances does the system fall back to an LLM to generate an improvised teaching for missing parts.

6. **Honesty / Weak Match Indicator**:
   - Until 299-label conformal calibration is achieved (Invariant 3), `is_direct_answer` remains `False`.
   - The answer text concludes with the calibrated honesty label:
     `Related, not a direct answer`
   - Future wording updates per task **E3** will preserve `is_direct_answer=False`.

7. **Sources Block (Footer)**:
   - Separated by horizontal rule `---`.
   - Format: `Sources: [1] <Talk Title> @ <MM:SS> · [2] <Talk Title> @ <MM:SS>`
   - Link references are footnotes only, never embedded within teaching prose.

## 4. Structured JSON Schemas

### 4.1 Direct First-Person Query Response (`FirstPersonQueryResponse`)

```typescript
export interface FirstPersonQueryResponse {
  answer_text: string;
  citations: FirstPersonCitation[];
  status: 'success' | 'weak_match' | 'abstained' | 'crisis_redirect' | 'error';
  is_direct_answer: boolean; // Always false until 299-label calibration
  latency_ms: number;
  cached: boolean;
  error?: string | null;
  answerability?: 'yes' | 'no' | 'indeterminate' | null;
  abstain_reason?: string | null;
  audio_playback_clip?: AudioPlaybackClip | null;
  audio_playback_clips: AudioPlaybackClip[]; // Array matching served quotes
  detected_concepts: string[];
  atma_vichara_inquiry?: string | null;
  practice_recommendation?: PracticeRecommendation | null;
}
```

### 4.2 Citation Contract (`FirstPersonCitation`)

```typescript
export interface FirstPersonCitation {
  video_id: string;
  point_id?: string | null;
  title?: string | null;
  url?: string | null;
  start_ms: number;
  end_ms: number;
  start_sec?: number;
  end_sec?: number;
  timestamp_seconds: number;
  speaker: string;
  teacher_id?: string | null;
  speaker_verified: boolean; // Falsy must render as unverified in UI
  channel?: string | null;
  transcript_hash: string;   // 64-character SHA-256 hex string
  verbatim_text: string;     // Exact transcript text
  text_snippet: string;
  source_url: string;        // Full YouTube URL with &t= start
  video_url: string;         // Base YouTube video URL
  playback_start_seconds?: number;
  playback_end_seconds?: number;
  playback_url?: string;
  confidence: number;
  is_verbatim: true;         // Always true for first-person clips
  provenance_kind: string;   // e.g. "speech_turn_clip" | "weak_match_fallback"
  caption_status: string;    // e.g. "manual_transcript" | "auto_transcript"
  facet?: string | null;     // Facet/topic heading if part of compound query
}
```

### 4.3 Audio Playback Clip Contract (`AudioPlaybackClip`)

```typescript
export interface AudioPlaybackClip {
  video_id: string;
  title: string;
  url: string;
  start_ms: number;
  end_ms: number;
  start_sec: number;
  end_sec: number;
  speaker: string;
  speaker_verified: boolean;
  playback_url: string;
  facet?: string | null;
}
```

### 4.4 Main Chat Bridge Pipeline Result (`PipelineResult`)

In `POST /api/chat` and `POST /api/chat/stream`, `FirstPersonBridgeStage` returns a `PipelineResult` with the following contract:

```typescript
export interface ChatFirstPersonBridgeResult {
  final_answer: string;      // Matches section 3 markdown layout
  intent: 'QUERY';
  route_decision: 'first_person_bridge' | 'first_person_abstain';
  model_used: null;          // Invariant: zero generative LLM on verbatim route
  model_provider: null;
  query_tier: 'fast';
  citations: FirstPersonCitation[];
  citations_verified: true;
  faithfulness_score: null;  // Not computed for verbatim clips
  hallucination_flag: false;
  verification: {
    passed: true;
    method: 'first_person_verbatim_clip_gate' | 'first_person_no_match_abstain' | 'first_person_store_unavailable';
    citations_verified: true;
    direct: boolean;         // False for weak_match
  };
  route_metadata: {
    requested_variant: 'first_person';
    selected_variant: 'verbatim_clip_bridge' | 'no_match_abstain';
    decision_method: string;
    first_person_collection: string; // e.g. "first_person_v8"
    clips_served: number;
    pipeline_latency_ms: number;
    pipeline_cached: boolean;
    audio_playback_clip?: AudioPlaybackClip | null;
    audio_playback_clips: AudioPlaybackClip[]; // Plural: all audio clips for multi-quote answers
    detected_concepts: string[];
    atma_vichara_inquiry?: string | null;
    practice_recommendation?: PracticeRecommendation | null;
  };
}
```

## 5. UI Rendering Guidelines for Thread T5

1. **Headings & Blockquotes**:
   - Render `### On ...` using the app's standard typography tokens.
   - Render blockquotes with a left accent border (warm gold or neutral minimal, avoiding generic AI blue).
2. **Audio Strips (`audio_playback_clips`)**:
   - Thread T5 can synchronize audio strips with the `▶ MM:SS` markers in the markdown.
   - Clicking `▶ MM:SS` or the inline Listen button should trigger audio/video playback starting at `start_sec`.
3. **Citations & Footnotes**:
   - Footnote indicators `[1]`, `[2]` should link to or open the reference drawer.
   - The drawer displays the verified speaker, confidence score, transcript hash, and talk title.
4. **Honest Gaps**:
   - The text `I don't have a recording that answers this part yet.` should be rendered cleanly as an honest status, not an error state.
