# Latency and Retrieval Evidence Gates

**Status:** Active production policy, 2026-08-22

AskMukthiGuru must optimize for **useful latency**, not merely a lower wall-clock number. A change is accepted only when it improves the target latency distribution without degrading faithfulness, citation correctness, abstention quality, rights isolation, tenant isolation, or safety behavior. Results must be split by query class because averages hide comparative, multilingual, graph, and unsupported-query failures.

## Required evaluation matrix

Every candidate change must be evaluated against the same held-out set and the same production-like configuration. Each row records query class, query text or stable ID, expected entities, expected relation, relevant source segment IDs, retrieved IDs, NDCG@k, recall@k, precision@k, answer faithfulness, citation correctness, abstention correctness, p50/p95/p99 latency, timeout/error status, and rights/tenant-isolation status. Raw answers and retrieval manifests remain available for human review; model judges are signals rather than ground truth.

| Gate | Minimum evidence | Production action if absent or failed |
| --- | --- | --- |
| Retrieval ranking | Per-class NDCG/recall/precision compared with current production baseline; no protected class regression beyond the agreed tolerance | Keep current fusion and candidate depths |
| Answer quality | Faithfulness, citation correctness, answer relevancy, and abstention/false-refusal review | Keep current prompt, verifier, and fallback behavior |
| Latency | p50/p95/p99 and timeout rate by class, including cold and warm runs | Keep current path; optimize only isolated safe work |
| Safety and privacy | Distress, prompt-injection, rights quarantine, tenant isolation, and private-memory non-leak probes | Reject the change and roll back |
| Cost and capacity | Provider calls, tokens, CPU, memory, Qdrant payload size, and queue SLA | Do not trade cost for an unmeasured tail improvement |
| Rollback | Reversible configuration or deployment and a known-good revision | Do not activate |

## ONNX INT8 embedding migration

`EMBEDDING_BACKEND=onnx_int8` remains **off** for the serving collection while existing Qdrant vectors are fp32-produced. Approval requires a shadow or blue-green re-embedding of the complete collection, vector-dimension and cosine-compatibility checks, per-class NDCG/faithfulness/citation results, and warm/cold memory and latency measurements. A strong aggregate overlap score is insufficient. If any corpus source is unavailable, any protected category falls below its floor, or index/query vectors are not generated by the same compatible backend, fail closed and retain fp32.

## RRF/DBSF and candidate-depth changes

RRF constants, DBSF selection, dense/sparse prefetch multipliers, and candidate limits must be changed only in a held-out comparison against the current production settings. Evaluate exact identifiers, semantic paraphrases, multilingual queries, comparative questions, unsupported questions, stale/rights-blocked sources, and multi-hop questions. The candidate is accepted only when ranking and answer-quality floors hold while p95/p99 and Qdrant resource cost improve or remain within the approved budget. Do not infer quality from one successful answer.

## Neo4j schema mutations

Neo4j indexes and constraints must be applied through an idempotent, lock-protected maintenance operation with a pre-change schema snapshot, health check, bounded execution timeout, post-change query-plan check, and rollback note. The operation must be isolated from user-serving requests and must not rewrite doctrine or personal-memory data. A schema mutation is not a latency optimization until representative graph queries demonstrate lower tail latency without increasing timeouts or changing tenant/corpus/rights semantics.

## Graph parallelization

Only independent, read-only graph branches may be parallelized. Their state writes must use explicit reducers or isolated result fields, their concurrency must be capped to host and Neo4j capacity, and a timeout on any branch must fail open to the vector path. The canary must compare graph-enabled and Qdrant-only runs for answer faithfulness, provenance completeness, graph timeout rate, p95/p99 latency, and resource usage. Do not parallelize branches that mutate shared state, rely on ordering, or may expose private memory through values streaming.

## Current safe changes and deployment boundary

The repository head contains two changes that do not alter retrieval evidence: a narrow English bounded-comparison short-circuit after input and distress guardrails, and a five-second translation deadline with fail-open multilingual behavior. English messages under an Indic UI preference skip redundant input translation; native Indic and code-switched text retain translation and guardrail coverage. The bounded-comparison shortcut is active in production through `8655709`. The translation-timeout and multilingual evidence-retry changes are pushed, but Railway has not promoted them: the attempted snapshots failed during initialization before Build/Deploy. All other gated defaults remain unchanged in production.
