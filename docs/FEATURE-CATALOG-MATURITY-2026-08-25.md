# Feature Catalogue and Maturity Matrix

This is the working source of truth for the feature-by-feature audit requested in the attached brief. A feature is not considered complete because a route, API function, or test exists. Each row must eventually have executable evidence for user entry, parsing, auth, authorization, validation, orchestration, dependencies, persistence, output, telemetry, failure, concurrency, cost, UX, and recovery.

The maturity scale is: **L0 Missing**, **L1 Prototype**, **L2 Functional**, **L3 Robust**, **L4 Production-grade**, **L5 Advanced**, and **L6 Best-in-class**. Current levels are conservative and reflect verified evidence, not aspirations.

## Mandatory per-feature execution record

For every row, the audit record must include: exact entry point; input schema and validation; identity/authz; downstream calls; state mutations; dependency timeout/retry/fallback; idempotency and concurrency behavior; user-visible loading/error/empty state; logs/metrics/traces; security/privacy review; cost and latency measurements; unit/contract/integration/E2E/chaos evidence; deployment/rollback; recovery; current level; target level; rationale; and the regression or benchmark that protects the improvement.

## Cross-feature combinations to test

The highest-risk combinations are anonymous/authenticated chat with quota and cache, chat with uploads and provider fallback, chat with memory and vault state, Profile Memory versus My Reflections, practices plus progress plus SRS, authentication expiry during streaming, ingestion plus retrieval plus cache invalidation, admin maintenance plus queue processing, and mobile offline retry plus idempotent mutations. These combinations can fail even when each feature passes in isolation.
