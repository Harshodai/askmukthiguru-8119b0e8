# B1 — Human gold-set review protocol

Scope: how humans build and label the gold evaluation set for the
first-person verbatim answer path. Tooling that implements this lives in
`backend/evaluation/gold/`. Source requirements: B1 in
`docs/agent/first_person_baseline_prompt.md` and section 8 of
`docs/agent/first_person_research_2026-09-24.md`.

**`golden_dataset.json`, `golden_qa_bank.json`, and any other LLM-generated
question set in `backend/evaluation/` are regression material only.** They
were generated from (or against) the corpus they test, so they cannot prove
accuracy — a system can overfit to phrasing it was measured against. Use them
to catch regressions between code changes, never to claim a precision or
coverage number.

## Question sources

- **Real, seeker-style questions**, written by people who have **not seen the
  target passage or transcript** — they know the topic area / video title at
  most, never the answer clip. Writing a question from the passage you're
  scoring it against is circular (arXiv 2412.17156).
- **Logged real user questions**, admitted only after de-identification
  (strip any PII, session IDs, free-text that could identify the asker).
- Never questions generated by an LLM reading the target chunk.

## Question mix

Target roughly **60% answerable / 20% near-miss / 20% unanswerable** per
batch. Near-miss = a question that sounds answerable but the corpus only
half-covers it (wrong specificity, adjacent topic, multi-part question where
only one part is covered). Unanswerable = genuinely outside the corpus.

## Acceptable-answer sets and equivalence groups

A single question can have more than one acceptable clip:

- **Pool candidates from several retrievers** before judging (R0/R1/R2 in the
  bake-off harness, or any future retriever set) — judging only one
  retriever's top-k biases the gold set toward that retriever (pooling bias,
  Sanderson & Zobel 2007).
- **Equivalent-teaching groups**: when the same teaching point is made in
  more than one clip/video, group those clip ids under one `equivalent_group`
  id at judging time. A hit on any clip in the group counts as correct at the
  group level; strict scoring still requires the single intended clip.

## Annotators, adjudication, agreement

- **Two binary annotators** per relevance judgment (does this clip answer
  this question — yes/no) and per transcript-quality judgment.
- **Adjudication rule**: annotators agree → that label stands. They disagree
  → a third reviewer (or the original protocol owner) adjudicates and that
  becomes `adjudicated`. Record both raw judgments and the adjudicated value;
  never overwrite the raw columns.
- **Report Cohen's κ** on every batch. Low κ (TREC DL sees 0.31–0.47) is
  expected and does not invalidate the set — system rankings stay stable at
  τ 0.879 even at that κ — but κ must be reported, not hidden.
- If an LLM judge is ever substituted for a human pass, validate it against
  ≥50 human-passed and ≥50 human-failed examples first (Hamel Husain's
  evals FAQ) before trusting its labels.

## Sampling constraints

- **At most 3 questions per video** in any single batch, to avoid one video
  dominating the confident-answer denominator and to keep clustered variance
  bounded (errors cluster by video and can inflate standard error up to 3×;
  arXiv 2411.00640).
- **Video-level held-out split** (`backend/evaluation/gold/split.py`):
  a video's questions live entirely in `held_out` or entirely in
  `dev_pool` — never split across both. This is what makes the held-out set
  usable as a launch gate instead of a set the system has already been tuned
  against.

## Transcript gold labelling

For a sampled subset of videos, label a **transcript gold segment**:

- 10-minute (600s) windows of the video.
- Verbatim words (not the cleaned/corrected transcript) — corpus filler-word
  stripping and correction happen downstream; the gold layer must reflect
  what was actually said.
- Speaker turns (who is speaking, including host vs. teacher).
- Word-level timestamps on the subset chosen for timestamp-error
  measurement.

## Clip-quality labels

For pooled candidate clips: a binary/ordinal quality label per clip
(clean cut, mid-sentence cut, audio issue, wrong language, other) recorded
alongside the relevance judgment — this is what feeds `verbatim-mismatch` and
future clip-boundary tuning, not model score.

## Scale

- **Pilot: 150 questions first**, over held-out videos, before scaling
  further.
- **Target: ~2,000 questions over time.** Section 8's Clopper–Pearson sizing
  needs ~628 *confident answers* (not raw questions) for a 1% upper bound
  allowing 2 errors, and ~2,000-2,500 confident answers for 80% power at true
  precision 99.5% — at an estimated 30% coverage that is roughly 2,000-2,600
  questions, hence the ~2,000 target.
- Refresh 20% of the frozen held-out set each quarter; keep a quarter-over-
  quarter diff so a refreshed set is never silently a different set.

## What this protocol does not cover

Scoring definitions (precision, coverage, abstention, top-1/top-3 strict and
group, wrong-speaker rate, timestamp error, verbatim-mismatch rate, the
Clopper–Pearson bound, and the clustered bootstrap) live in
`backend/evaluation/gold/metrics.py`, ported from
`/Users/harshodaikolluru/mukthiguru_attribution_data/bakeoff_2026-09-25/scoring.py`
and `scoring_lib.py`. This document is the human labelling process; that
module is the arithmetic.
