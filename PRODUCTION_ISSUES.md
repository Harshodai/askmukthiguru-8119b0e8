## Localhost safety-order hardening — 2026-08-23

The resumed localhost audit identified a genuine safety-order defect in the default pipeline: `CircuitBreakerStage` preceded `InputGuardrailStage`, so an open provider circuit could short-circuit before deterministic input safety evaluation. The scoped fix moves `InputGuardrailStage` ahead of `CircuitBreakerStage` and keeps provider distress-classifier failures indeterminate rather than invoking degraded intent classification. Unblocked `ERROR` and `TIMEOUT` results now map to `grounding_state=system_error`, keeping provider outages distinct from both safety redirects and ordinary doctrine abstentions.

Desktop Docker validation passed **84 tests in 9.81 seconds** across provider-failure, distress-regex, crisis-preemption, and fail-closed paths. A metadata-only localhost probe returned the acute self-harm control as blocked `DISTRESS`; the benign Beautiful State control returned `QUERY` with `no_context_short_circuit` because the selected local Qdrant collection has zero points. Local `/api/health` returned HTTP 200 with `ready=true,status=degraded`, with optional OCR as the reported degraded component. These results validate the safety and routing behavior of the local source, but they do not validate production retrieval quality, citations, provider credentials, or deployment state.

This item is **VERIFIED LOCALLY / NOT A PRODUCTION READINESS CLOSURE**. No Railway deployment was started, no corpus files were modified, and no unrelated desktop project was changed.

## Closure rule
